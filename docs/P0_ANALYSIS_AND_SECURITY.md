# PARKDA 2.0 — P0 분석 및 보안 점검

작성 기준: `feature/parkda-2` 브랜치, 저장소 `kimmyungrae80/parkda` (**공개(PUBLIC) 저장소**).
이 문서에는 키·비밀번호·개인정보의 실제 값을 적지 않는다. 위치(줄 번호)만 기록한다.

### 확인된 사실 요약
- 공개 저장소 + 소스 내 키 → 누구나 키를 복사할 수 있음 (1, 3번)
- Supabase **anon** 키 자체는 설계상 공개 값이지만, 보호는 RLS 정책에만 의존함 (JWT 페이로드의 `role`이 `anon`임을 확인)
- 관리자 기능은 실질적으로 보호되지 않음 (2번)

## 3. 이 브랜치에서 실제로 바꾼 것

- `index.html`: `escHtml`, `safeUrl`, `safeId` 헬퍼 추가, 외부 데이터 삽입 10곳 적용. 기능·디자인 변경 없음.
- `supabase/audit/parkda_store_readonly_audit.sql`: 읽기 전용 점검 쿼리 (데이터 변경 없음).
- `docs/P0_ANALYSIS_AND_SECURITY.md`: 이 문서.

검증:
- 두 인라인 스크립트 문법 검사 통과 (`new Function` 파싱)
- 헬퍼 단위 테스트: `<img onerror>`·`<script>` 이스케이프, `javascript:` 링크 차단, 악성 유튜브 ID 차단 확인

## 4. 소유자 조치가 필요한 항목 (승인 필요)

1. **키 폐기·재발급**: YouTube API 키, 카카오 REST 키 (Google Cloud / Kakao Developers 콘솔)
2. **관리자 비밀번호 변경**, 그리고 소스에서 제거 (서버 권한으로 대체 전까지 임시 조치)
3. **저장소 공개 여부 결정**: 공개 상태이면 키 재발급 전까지 노출 지속
4. **Supabase RLS 점검**: `supabase/audit/parkda_store_readonly_audit.sql` 실행 결과 공유 요청
5. 히스토리에 남은 키 제거(`git filter-repo` 등)는 파괴적 작업이므로 별도 승인 후 진행
