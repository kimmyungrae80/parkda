# PARKDA 2.0 서버 연결 현황 (2026-10-30)

## 결론
- **실제 서버 연결은 완료되지 않았습니다.** 테스트용 Supabase 프로젝트가 없어서 카카오 로그인, 동호회·모임·경기 데이터를 실서버에 연결하지 못했습니다.
- 대신 서버 쪽 규칙(스키마, 권한 정책, 쓰기 함수)을 로컬 PostgreSQL 17 에서 실제로 실행하고 검증했습니다.
- 운영 Supabase 프로젝트, 운영 main, 운영 도메인은 건드리지 않았습니다.

## 1. 점수 저장 상태 (화면 연결 완료, 테스트 완료)
| 상태 | 문구 | 표시 조건 |
|---|---|---|
| 로컬 저장 중 | 이 기기에 저장 중… | 서버 설정이 없을 때 (기본) |
| 서버 저장 중 | 서버에 저장 중… | 서버 설정이 켜졌을 때 |
| 서버 저장 완료 | 서버에 저장됨 · HH:MM | 서버 응답 성공 (데모에서는 발생하지 않음) |
| 로컬 저장 완료 | 이 기기에 저장됨 · HH:MM | 서버 설정이 없을 때 |
| 오류 | 저장하지 못했습니다. 다시 시도해 주세요. | 서버 저장 실패 |

- `dbSave` 가 `local` / `server` / `failed` 를 반환하고, `autoSaveNow` 가 그에 맞는 문구만 보여줍니다.
- 테스트: `tests/e2e/test_score_screen.py` 38/38 (데모에서 "서버에 저장됨"이 나오지 않음, 서버 설정만 켰을 때 실패 문구 확인).

## 2. 서버 스키마와 쓰기 함수 (로컬 DB 검증 완료)
- `supabase/staging/0001_platform_schema.sql`: 테이블 15개, RLS 15개 테이블, 정책 24개 (기존 파일)
- `supabase/staging/0002_write_functions.sql`: 쓰기 함수 10개 (신규)
  - 동호회: `request_join`, `decide_member` (운영자만 승인·거절, 감사 로그 기록)
  - 함께 치기: `create_meetup`, `join_meetup` (모임 행 잠금으로 정원 초과 방지, 대기 순서 유지), `cancel_join` (대기자 자동 승격)
  - 경기: `create_game`, `set_game_paused`, `submit_score` (범위·선수·상태 검증, 변경 전 값 기록), `confirm_result` (모든 홀 입력 필요, 동점 공동 순위), `unlock_final` (사유 필수)
- 이유: RLS 정책에는 승인·참가·점수 입력을 허용하는 직접 쓰기 정책이 없어서, 이 기능들은 함수를 거치지 않으면 실행되지 않습니다. 테스트에서 직접 UPDATE 가 0건으로 막히는 것을 확인했습니다.

### 검증 결과 (`tests/db/staging_rls_test.js`)
- 실행: 로컬 PostgreSQL 17 (embedded 바이너리, 임시 DB `parkda_test`). 결과 **16/16 통과**.
- 포함 항목: 외부인 회원 목록 차단, 직접 승인 차단, 운영자 승인 성공, 일반 회원 승인 거부, **동시 신청 10명 → 정원 2 모임에 참가 2명만**, 대기 승격, 중복 참가 거부, 외부인 참가 거부, 점수 범위·선수·홀 검증, 외부인 점수 입력 거부와 조회 0건, 점수 이력, 중단 중 입력 차단, 결과 확정·동점 순위, 확정 후 잠금 해제 사유, 익명 사용자 함수 호출 거부.
- **한계**: Supabase 의 GoTrue(로그인)와 PostgREST(API)는 없습니다. `auth.uid()` 와 `anon`·`authenticated` 역할은 최소한으로 흉내 냈습니다. 실제 JWT 가 권한을 어떻게 전달하는지는 스테이징에서 다시 확인해야 합니다.
- 테스트는 `PARKDA_TEST_PG_SOCKET` 또는 `PARKDA_TEST_PG_HOST` 가 없으면 건너뜁니다. 건너뛴 결과는 통과로 보고하지 않습니다.

## 3. 아직 연결되지 않은 것
- **카카오 로그인 (Supabase Auth)**: 스테이징 프로젝트와 카카오 앱 설정이 필요합니다. `auth/kakao-auth.js` 는 설정 확인 모듈(테스트 5/5)만 있고 실제 로그인은 실행하지 않았습니다. 이름이 같은 사람을 구분하는 서버 사용자 ID 도 아직 프론트엔드에 연결되지 않았습니다.
- **프론트엔드 → 서버 호출**: 동호회, 모임, 경기 화면은 여전히 이 기기 데모 데이터(localStorage)를 씁니다. 함수는 있지만 화면에서 호출하지 않습니다.
- **Club Pro 서버 연결**: 회비 장부·구독 권한 검증은 테이블과 정책만 있고 함수가 없습니다. 구독 권한 검증 함수는 아직 작성하지 않았습니다.
- **두 브라우저 실사용 검증**: 데모는 기기마다 데이터가 따로라서 두 사용자가 같은 모임을 보는 흐름을 검증할 수 없습니다. 서버 연결 후 검증합니다.
- **CSV 다운로드 (실제 데이터 기반)**: 데모 데이터 CSV 만 있습니다.

## 4. 운영 전환 전 필요한 조건
1. parkda 전용 테스트 Supabase 프로젝트 생성 (소유자 또는 권한 규칙 승인 필요). 운영 프로젝트 `szoxnkarkdxirbyxmzgr` 는 사용하지 않습니다.
2. 스테이징에 0001, 0002 적용 후 `tests/db/staging_rls_test.js` 를 스테이징 연결로 실행 (실제 JWT 경로 포함).
3. 카카오 로그인 설정과 실제 로그인 테스트, 사용자 ID 매핑.
4. 프론트엔드의 동호회·모임·경기 화면을 서버 호출로 바꾸고, 두 브라우저 검증.
5. 보안 점검: 비밀키는 서버 환경 변수로만 보관, 클라이언트에 노출 금지, 개인정보(전화번호)는 저장하지 않음 (0001 원칙).
6. 소유자 승인 후 운영 전환 (별도 절차, 이번 작업 범위 밖).
