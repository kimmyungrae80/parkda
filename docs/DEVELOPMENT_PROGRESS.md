## 데모 기능 (서버 검증 없음 — 운영 사용 금지)
- 함께 치기, 동호회: 모든 데이터는 `localStorage` 에만 있다. 운영자 여부는 표시 이름 일치로만 판단한다. 브라우저에서 바꿀 수 있으므로 **운영 권한 판단에 쓰면 안 된다.** 화면에 "데모" 안내를 표시한다.

## 아직 구현하지 않은 것 (정직한 목록)
- **P3-1 회원 인증**: Supabase Auth 세션, 카카오 인증 연동, 기존 이름·전화번호 데이터 매핑·동의 절차 — 설계 문서만 있음. 테스트 DB 없이 실제 인증을 구현·검증할 수 없음.
- **P3-2 동호회 나머지**: 탈퇴, 가입 거절, 회원 목록 화면, 총무 역할, 출석 관리.
- **P3-3 함께 치기 나머지**: 대기자 등록, 공유 기능, 신고·차단, 지역·구장별 검색 고도화.
- **P4 경기관리 통합 나머지**: 조편성 수동 수정, 경기 중단·재개, 점수 수정 이력, 동점 처리, 결과 확정·운영자 승인 후 수정, 동호회별 이력, 개인 누적 기록, 서버 측 점수 계산·검증. (기존 경기관리 화면은 그대로 유지)
- **P5 Club Pro**: 전부 미구현. 회비 장부·CSV·PDF·구독 화면 없음.
- **P6 결제·관리자·운영**: 결제 SDK 선택(승인 필요), 웹훅 서명 검증, 구독 상태, 관리자 콘솔, 감사 로그, 백업 절차 모두 미구현. 실제 결제 활성화는 금지 사항.
- **마이그레이션**: 작성만 했고 적용·검증하지 않음 (테스트 DB 필요).

## P3~P6 UI 통합 (데모, 2026-10-28)

모든 기능은 **이 기기의 localStorage 에만 저장**되며 운영 서버·운영 DB 를 호출하지 않는다. 권한은 화면 데모 수준이고 서버 권한이 아니다.

**아직 하지 않은 것 / 한계 (정직한 목록)**
- 조편성 수동 수정: 구현하지 않았다. 기존 자동 편성과 조장 변경만 있다.
- 결과 확정 후 수정: UI 는 승인 표시를 두고 저장 시 결과를 다시 계산하는 방식이다. `lib/score-logic.js` 의 `editAfterFinal` 은 단위 테스트만 있고 UI 에서 쓰지 않는다.
- 권한: 모든 역할 판단은 이 기기의 화면 데모다. 동명이인이 구분되지 않는다. 서버 인증·RLS 가 없으므로 실제 권한으로 쓸 수 없다.
- 차단 해제 화면이 없다 (테스트는 저장소를 직접 비운다).
- 정기모임 자동 생성은 없다 (수동 등록만).
- 회비 장부는 운영자가 입력하는 기록이며 실제 금융 거래가 아니다.
- 결제: 없음. "Pro 체험" 버튼은 이 기기에서 화면만 바꾼다. 구독·결제 상태와 무관하다.
- 관리자 콘솔: 개발용이며 `?dev=1` 로만 열린다. 운영 권한이 아니다.
- 구장 정보 수정 제보: 이 기기에만 저장되며 운영팀에 전달되지 않는다.
- 데이터 키 변경: 데모 저장 키를 `pd_demo_meetings_v2`, `pd_demo_clubs_v2` 로 바꿨다. 이전 데모 데이터(v1 키)는 읽지 않아 화면에 보이지 않는다.
- 운영 Supabase DB 접근, 운영 main 변경, 운영 도메인 배포, 실제 결제 활성화: 하지 않았다.
- 테스트 데이터 삭제: 실행하지 않았다 (`docs/TEST_DATA_CLEANUP_PLAN.md`, 초안 SQL 은 주석 처리).
