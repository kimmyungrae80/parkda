# PARKDA 2.0 화면 이동·로그인 구조 (2026-10-31)

## 화면 이동 (하단 메뉴 5개 고정: 홈 / 구장 / 모임 / 경기 / MY)
```
홈 ──┬─ 구장 찾기 ──── 구장 상세 (#/course/ID, 게임코드 링크와 같은 방식)
     ├─ 함께 치기 ──── 모임 만들기 · 참가 · 동호회 (pg-clubs, pg-club)
     ├─ 대회 정보 · 영상 · 맛집 (홈 하단 "더 알아보기")
     ├─ 경기 (로그인 필요) ── 경기관리 허브 (pg-mgmt)
     │      ├─ 경기 만들기 ── 경기 정보 입력 ── 조편성 (pg-groups)
     │      │                                     └─ 참가자 조 이동·조장 변경·확정
     │      ├─ 진행 중인 경기 카드 ── 점수 입력 (pg-score) ── 결과 확정 ── 결과 (pg-result)
     │      ├─ 완료된 경기 카드 ──── 결과 보기 (pg-result)
     │      └─ 게임코드로 참가
     └─ MY (pg-my) ── 로그인 상태 · 경기관리 · 동호회 · 로그아웃 → 공개 홈
```
- "경기 목록"(pg-matches)은 경기관리 허브로 통합됐습니다. 이전 링크는 허브로 이동합니다.
- 경기 화면마다 헤더의 **홈** 버튼이 있고, 점수 입력 하단에는 **이전 화면 · 경기 목록 · 홈**이 있습니다.
- 결과 화면 하단에는 **내 경기로 · 홈으로**가 있습니다.

## 로그인 상태 (하나로 관리)
- 상태 저장소: `localStorage` 의 `pd_user` 하나. 서버 인증이 아니며 MY 화면에 "이 기기에서만 유지되는 로그인 (서버 인증 아님)"으로 표시합니다.
- 로그인이 필요한 화면(`needLogin`)은 목표 화면을 기억한 뒤 로그인 화면으로 보냅니다. 로그인 성공 시 (`finishLogin`) 그 화면으로 돌아가며, 로그인 화면은 기록에서 대체되어 뒤로가기로 다시 나타나지 않습니다.
- 이미 로그인한 상태에서는 경기관리 진입 시 로그인 화면이 나오지 않습니다.
- 로그아웃은 공개 홈으로 이동합니다.
- 공개 정보(구장·대회·영상·모임 목록)는 로그인 없이 볼 수 있습니다.

## 뒤로가기
- `go()` 가 화면 이동마다 브라우저 기록을 남기고, `popstate` 로 기록을 따라갑니다.
- 점수 입력 중 화면을 떠나면 대기 중인 자동 저장을 먼저 실행합니다. 저장 상태는 화면에 "이 기기에 저장됨" 또는 실패 문구로 표시됩니다.

## 기존 데이터·계산
- 경기 데이터 구조(`S.matches`, `groups`, `sd`, `scoreLog`, `final`)와 점수·순위 계산 로직은 바꾸지 않았습니다.
- 조편성 이동은 이름 기준이라 점수 기록은 그대로 유지됩니다.
- 게임코드 링크(`?game=`)와 `#/course/ID` 링크는 그대로 동작합니다.

## 아직 남은 한계
- 실제 Supabase 로그인과 서버 저장은 연결되지 않았습니다 (`docs/SERVER_STATUS.md`).
- 결과 공유(카카오톡)는 기존 기능을 유지했을 뿐, 실제 카카오 앱 공유는 이 환경에서 확인하지 못했습니다.
- 경기관리 화면의 세부 디자인(조편성 카드 배치 등)은 기존 토스 스타일 토큰을 따르지만, 조편성 화면은 캡처 검토를 하지 못했습니다.
